# МарИИя — AI-нутрициолог для Salebot

Python-сервис, который Salebot вызывает через webhook, когда платный подписчик
хочет составить рацион. МарИИя использует ТОЛЬКО рецепты из сборника Марии
Дивисенко (250 шт), помнит каждого клиента и учится на разговорах.

## Два режима работы

МарИИя умеет работать в двух режимах — они переключаются через **Custom Start
Command** в Railway Settings:

1. **Telegram-режим** (для теста и отладки) — `python telegram_bot.py`.
   МарИИя живёт как обычный Telegram-бот. Ты создаёшь отдельного тестового
   бота в @BotFather, говоришь с ним напрямую, проверяешь как она отвечает
   на твои запросы. Salebot не нужен.

2. **FastAPI-режим** (для продакшена) — `uvicorn main:app --host 0.0.0.0 --port $PORT`.
   МарИИя становится HTTP-сервисом, который Salebot дёргает webhook'ом.

**Сначала всегда тестируй в Telegram-режиме**, прежде чем подключать Salebot.
Это сильно ускоряет отладку — ты видишь как она отвечает живьём, без посредников.

## Структура файлов

- `telegram_bot.py` — Telegram-бот для тестирования (режим 1)
- `main.py` — FastAPI приложение для Salebot (режим 2)
- `mariya.py` — мозги: общение с Claude, валидация. Используется обоими режимами.
- `storage.py` — SQLite (клиенты, диалоги, факты). Тоже общая для обоих.
- `recipes.json` — база рецептов (232 записи, спарсенные из PDF)
- `parse_recipes.py` — скрипт парсинга PDF (если будешь дополнять сборник)
- `requirements.txt` — зависимости
- `Procfile` — команда запуска (по умолчанию Telegram-режим)
- `.env.example` — шаблон переменных окружения

## Этап 0. Тестирование в Telegram (ОБЯЗАТЕЛЬНО до Salebot)

### 0.1. Создай отдельного тестового Telegram-бота

@BotFather → `/newbot` → имя `Мария Тест` → юзернейм например `maria_test_bot`.
Сохрани токен. Это ОТДЕЛЬНЫЙ бот от твоего основного — чтобы не мешали друг другу.

### 0.2. Задеплой МарИИю на Railway в Telegram-режиме

Действуй как с предыдущим ботом: новый репозиторий на GitHub, деплой на Railway.
В Variables на сервисе:

| Переменная | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather (из шага 0.1) |
| `ANTHROPIC_API_KEY` | тот же что у основного бота |
| `DB_PATH` | `/data/mariya_data.db` (или `mariya_data.db` если нет Volume) |
| `RECIPES_PATH` | `recipes.json` |

`Procfile` уже настроен на Telegram-режим (`python telegram_bot.py`) — ничего
не меняй.

### 0.3. Тестируй

Найди своего тестового бота в Telegram, напиши `/start`. Дальше:

```
Привет, я твой клиент. Меня зовут Назир. Моя цель — похудение.
Целевая калорийность 1700 ккал, БЖУ 130/55/180.
Я не люблю курицу и рыбу, но люблю сладкое.
Составь рацион на день.
```

МарИИя должна:
1. Учесть, что ты не ешь курицу и рыбу.
2. Подобрать блюда из СБОРНИКА (не из головы) — десерты, овощные блюда, мясо
   кроме курицы, гарниры.
3. Посчитать суммарный КБЖУ и показать его.
4. В конце предложить следующий шаг.

Дальше задай ей разные вопросы: «составь рацион на неделю», «найди десерт до
200 ккал», «замени завтрак на что-то с творогом». Проверь насколько чётко она
держится твоих рамок и насколько точно работает с КБЖУ.

`/profile` покажет что она про тебя запомнила. `/forget` — забудет диалог.
`/reset` — снесёт всё.

### 0.4. Если что-то не нравится

- Слишком общие ответы → допиши в `mariya.py` в `MAIN_SYSTEM_INSTRUCTION` уточнений
- Галлюцинирует рецепты → переключи модель на Opus (`CLAUDE_MODEL=claude-opus-4-6`)
- Плохо суммирует КБЖУ → добавь правило «дважды проверь арифметику»
- Не помнит то что сказал → проверь что Volume подключён (иначе при редеплое
  всё забывается)

### 0.5. Когда устроит — переключайся в FastAPI-режим

В Railway Settings → найди **Custom Start Command** (или **Start Command**) и
поставь:
```
uvicorn main:app --host 0.0.0.0 --port $PORT
```

Дальше иди по разделу «Этап 1» ниже (но многое уже сделано — нужно только
добавить `API_SECRET` в Variables и включить публичный URL).

После этого тестового бота можно либо оставить параллельно (для своих экспериментов),
либо снести из BotFather когда не нужен.

## Этап 1. Деплой Python-сервиса на Railway

### 1.1. Положи файлы в новый GitHub-репозиторий

Создай новый репозиторий (например `mariya-ai`) и загрузи:
- `main.py`, `mariya.py`, `storage.py`
- `recipes.json`
- `requirements.txt` (переименуй `requirements-mariya.txt` → `requirements.txt`)
- `Procfile` (переименуй `Procfile-mariya` → `Procfile`)
- `.gitignore` (можно из старого проекта)
- `README.md` (этот файл)

ВАЖНО: `.env` НЕ загружай в репозиторий.

### 1.2. Создай сервис в Railway

1. https://railway.app → **New Project** → **Deploy from GitHub repo** → выбери `mariya-ai`.
2. Дождись первой сборки (упадёт из-за отсутствующих переменных — это норма).

### 1.3. Заполни переменные окружения

В сервисе → **Variables** → добавь:

| Переменная | Значение | Зачем |
|---|---|---|
| `ANTHROPIC_API_KEY` | `sk-ant-...` | Ключ Claude (можно тот же что у основного бота) |
| `API_SECRET` | придумай длинную случайную строку, например `mariya_secret_2026_aB7XzKpQwR3` | Авторизация запросов от Salebot |
| `CLAUDE_MODEL` | `claude-sonnet-4-6` | Модель для ответов |
| `LEARN_MODEL` | `claude-haiku-4-5-20251001` | Дешёвая модель для авто-обучения |
| `DB_PATH` | `/data/mariya_data.db` | Путь к БД (если есть Volume) или `mariya_data.db` |
| `RECIPES_PATH` | `recipes.json` | Где лежит база рецептов |

### 1.4. Подключи Volume (важно для памяти клиентов)

В **Settings → Volumes** создай Volume, mount path `/data`. Без него профили
и история диалогов клиентов будут сбрасываться при каждом редеплое.

### 1.5. Получи публичный URL

В **Settings → Networking** включи **Public Networking** → **Generate Domain**.
Получишь URL вида `https://mariya-ai-production.up.railway.app`. Это твой
endpoint для Salebot.

### 1.6. Проверь что работает

Открой в браузере: `https://твой-url.up.railway.app/` — должно показать:
```json
{"name":"МарИИя","version":"1.0","recipes_loaded":232}
```

И `https://твой-url.up.railway.app/health` → `{"status":"ok"}`.

В Deploy Logs должна быть строка:
```
МарИИя готова (model=claude-sonnet-4-6, db=/data/mariya_data.db)
Загружено рецептов: 232
```

## Этап 2. Интеграция с Salebot

### 2.1. Идея

В Salebot создаёшь кнопку «Поговорить с МарИИей». При нажатии:
1. Клиент переключается в режим «свободный ввод».
2. Каждое его сообщение Salebot отправляет POST на наш `/chat`.
3. Получает обратно текст ответа МарИИи и пересылает клиенту.
4. Клиент пишет «выйти» / жмёт кнопку → возвращается в обычное меню.

### 2.2. Пошагово в Salebot

#### Шаг А. Создай блок «Кнопка — Поговорить с МарИИей»

В сценарии бота (там где главное меню) добавь кнопку с текстом
«🥗 Поговорить с МарИИей». При нажатии переход на новый блок.

#### Шаг Б. Проверка подписки

Перед запуском МарИИи проверь что у клиента есть активная подписка. Используй
свой стандартный блок проверки (тот, что охраняет рецепты). Если подписки нет
— покажи сообщение «Доступно по подписке» и кнопку «Оплатить».

#### Шаг В. Блок «Приветствие МарИИи»

Сообщение клиенту:
```
Привет, я МарИИя — твой нутрициолог.
Расскажи свою цель и я подберу тебе рацион из сборника Марии.
Например: «составь рацион на день на 1500 ккал, БЖУ 120/100/50,
не люблю курицу и рыбу».

Чтобы выйти из диалога со мной — нажми кнопку «Выйти» ниже.
```

Внизу — кнопка «Выйти» (возвращает в главное меню).

#### Шаг Г. Блок «Ожидание ввода клиента»

Создай блок, который принимает любой текст от клиента и сохраняет его в
переменную, например `{user_input}`.

#### Шаг Д. Блок «API-запрос к МарИИе»

Это главный блок. В Salebot называется «**Запрос к API**» (или «Внешний сервис» /
«HTTP-запрос» — точное название зависит от версии).

Настройки:

- **Метод:** `POST`
- **URL:** `https://твой-url.up.railway.app/chat`
- **Заголовки (Headers):**
  ```
  Content-Type: application/json
  X-API-Key: твой-API_SECRET-из-Railway
  ```
- **Тело запроса (Body, формат JSON):**
  ```json
  {
    "user_id": "{user_id}",
    "name": "{name}",
    "message": "{user_input}"
  }
  ```
  где `{user_id}` — встроенная переменная Salebot (стабильный ID клиента),
  `{name}` — имя клиента, `{user_input}` — текст что он только что написал.

- **Обработка ответа:** ответ придёт в формате `{"reply": "..."}`. Salebot
  должен достать поле `reply` и положить в переменную, например `{mariya_answer}`.
  В Salebot это делается через настройку «Парсинг ответа» или
  «Извлечь значение по пути» → `$.reply`.

#### Шаг Е. Блок «Показать ответ МарИИи»

Сообщение клиенту:
```
{mariya_answer}
```

После этого — переход обратно на блок «Ожидание ввода клиента» (Шаг Г), чтобы
клиент мог задать следующий вопрос. И снова — внизу кнопка «Выйти».

#### Шаг Ж. Блок «Выйти из диалога»

Кнопка «Выйти» ведёт сюда. Сообщение «Возвращаю тебя в меню» → переход на
главное меню бота.

### 2.3. Схема потока в одной картинке (текстом)

```
[Главное меню] → кнопка «Поговорить с МарИИей»
       ↓
[Проверка подписки] → нет → [Сообщение «Оплатите»]
       ↓ да
[Приветствие МарИИи] + кнопка «Выйти»
       ↓
[Ожидание ввода] → получили текст клиента
       ↓
[API-запрос POST /chat] → получили {"reply": "..."}
       ↓
[Показать ответ] → возврат к «Ожидание ввода»
       ↓ (либо нажал «Выйти»)
[Выйти из диалога] → [Главное меню]
```

## Этап 3. Дополнительные эндпоинты (опционально)

### 3.1. Явная установка профиля (онбординг)

При первом входе клиента в подписку можно через Salebot задать ему вопросы
(имя, цель, КБЖУ, аллергии) и сразу записать в профиль МарИИи. Тогда первый
рацион получится с учётом всего этого, без переспросов.

Это блок «API-запрос» на `POST /profile`:

```json
{
  "user_id": "{user_id}",
  "name": "{name}",
  "target_kcal": 1500,
  "target_protein": 120,
  "target_fat": 50,
  "target_carbs": 100,
  "allergies": ["орехи"],
  "dislikes": ["курица", "рыба"],
  "likes": ["сладкое"]
}
```

Числа и массивы подставляешь из переменных Salebot, которые соберёшь на
онбординге.

### 3.2. Сброс памяти

Если клиент жмёт «Начать сначала» — Salebot вызывает `POST /forget` (стирает
диалог и факты, профиль сохраняет) или `POST /reset` (полный сброс).

Тело:
```json
{"user_id": "{user_id}"}
```

## Прогнозируемая стоимость

- Anthropic с prompt caching: ~$0.01–0.02 на один запрос.
- 100 клиентов × 5 запросов/день = ~$15–30/мес.
- Railway hobby: $5/мес.
- Webshare/прокси: не нужны (мы не парсим внешние сайты).

## Как обновить сборник рецептов

1. Положи новый PDF в репозиторий.
2. Запусти `python parse_recipes.py` локально → получишь свежий `recipes.json`.
3. Закоммить обновлённый `recipes.json` в GitHub.
4. Railway передеплоит, новые рецепты сразу подхватятся.

(Сейчас в `parse_recipes.py` путь к PDF захардкожен — поменяй на свой.)

## Тестирование без Salebot

Можешь дёрнуть `/chat` вручную из терминала чтобы проверить, что МарИИя
отвечает адекватно:

```bash
curl -X POST https://твой-url.up.railway.app/chat \
  -H "Content-Type: application/json" \
  -H "X-API-Key: твой-секрет" \
  -d '{"user_id":"test1","name":"Тестер","message":"Привет! Составь рацион на день на 1500 ккал, БЖУ 120/50/100, не люблю курицу и рыбу"}'
```

В ответе должен прийти JSON с готовым рационом из рецептов Маши.
